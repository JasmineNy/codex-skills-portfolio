# X-Humanoid 汇报PPT规则

## 1. 品牌与模板

- 内部述职、周期复盘、项目复盘和管理汇报默认使用 `assets/ppt模版01.pptx`。
- 外部演讲、客户汇报和公开展示默认使用 `assets/ppt模版02.pptx`。
- 用户明确指定01或02时以编号为准；未说明编号与受众时必须先追问。
- 公司模板是最终PPT唯一的品牌视觉来源。数据表达库只提供分析结构，不提供最终Logo、字体、配色或页脚。
- 不覆盖技能内的任何PPT资产；生成结果另存到用户指定位置。

## 2. 结论与叙事

- 每页只支持一个主结论，标题优先写成可验证的结论，不只写“数据分析”或“项目进展”。
- 内部汇报优先表达：目标、结果、差距、原因、风险、下一步和所需决策。
- 外部汇报优先表达：受众问题、价值主张、证据、方案、落地路径和行动建议。
- 文字过多时先压缩文案或拆页，不通过缩小字号强行塞入。

## 3. 数据完整性检查

每个图表使用前确认：

- 指标定义、单位、时间周期和统计口径一致。
- 比率指标具有明确的分子、分母和样本量。
- 对比组的范围、基期、币种、含税状态和价格口径可比。
- 实际值、目标值、估算值和预测值有明确区分。
- 预测标注假设、截止时间、模型或计算方法及不确定性。
- 缺失值、异常值、剔除项和数据局限已显式说明。
- 内部数据保留责任人或系统来源；外部数据保留可追溯链接、发布日期和引用口径。

## 4. 按数据量选择表达

| 数据条件 | 优先表达 | 禁止或警惕 |
|---|---|---|
| 1个核心数据 | 大数字、目标差异、进度或结论+证据 | 不为了视觉效果强行生成图表 |
| 2个数据 | 前后对比、成对柱状、差值标注 | 不用折线表达趋势 |
| 3–5个类别 | 排序条形或柱状 | 饼图/环形图仅限构成关系且合计为100% |
| 4个以上连续时点 | 折线图、面积图 | 预测段必须与实际段分隔 |
| 2–6个类别且多系列 | 分组柱状、堆叠柱状或长表 | 系列超过4个时优先拆页 |
| 至少6个可比观察值 | 散点图 | 两个轴必须是同一粒度的数值指标 |
| 至少10个观察值+3个数值变量 | 气泡图 | 气泡大小不得表示类别或无单位得分 |
| 因素可加总并能与结果勾稽 | 瀑布图或驱动分解 | 各因素无法与起点/终点勾稽时不使用 |

## 5. 小数据量适配

- 参考页面模块数量大于实际信息量时，删除多余模块并重新分配空间。
- 将稀疏数据表达为“结论+关键数字+必要证据”，不堆叠空图表。
- 不使用虚构对比组、复制数据点、伪造趋势或无样本支持的百分比。
- 类别超过6个时优先排序、合并为“其他”、只显示Top N或拆页；不缩小到无法阅读。
- 删除空白占位符后必须重新平衡页面，不留下明显的布局缺口。

## 6. 数据表达库复用

- 先查 `data-expression-index.json`，再打开对应原始页面，避免每次全量渲染214页。
- `chart-structure-reusable`：可复用图表结构，但必须替换全部数据、结论、标注、单位、来源和视觉样式。
- `logic-reference-only`：页面存在EMF/WMF、特殊填充、扩展图表或其他兼容风险，只参考逻辑，不复制对象。
- `layout-reference-only`：无可编辑图表，仅参考信息层级或分析流程。
- 无论直接复用或重建，都必须删除参考库的Logo、页脚、示例数据、英文占位文字和配色。

## 7. 对外信息安全门禁

发现以下内容时，在用户确认前不得进入最终外部PPT：

- 未公开客户名称、合作进展、合同条款或价格。
- 未公开经营数据、产品路线图、技术参数或上线计划。
- 个人手机、邮箱、微信、地址等直接联系信息。
- 无可追溯来源的市场规模、增长率、竞品数据或政策结论。

对风险内容列出原文、所在页、风险类型和处理选项：删除、匿名化、使用公开来源替换或用户明确批准。

## 8. 交付QA

- 逐页渲染检查遮挡、裁切、换行、占位符、页码、Logo和来源。
- 核对图表数值、轴范围、图例、颜色、标注、排序和页面结论。
- 检查饼图/环形图合计、比率分母、预测分界和各页数据口径一致性。
- 删除所有参考库品牌元素、示例数据、示例人名和未解决的默认占位文字。
- 完成PPT XML级占位符检查，确保不留空结构占位符。
